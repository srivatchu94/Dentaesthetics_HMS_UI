# Participant Registration Data Flow

## Overview
Complete flow for adding camp participants with proper data validation and API mapping.

## API Endpoint
```
[HttpPost("AddCampParticipant", Name = "AddCampParticipant")]
public IActionResult AddCampParticipant([FromBody] CampParticipantRegistrationModel participant)
```

**URL**: `POST https://localhost:7104/api/Camp/AddCampParticipant`

## Validation Rules (Frontend)

Before submission, the following validations occur:

| Field | Rule | Error Message |
|-------|------|---------------|
| campId | Must exist and > 0 | "Camp ID is missing! Please select a camp first." |
| participantName | Required, non-empty | "Participant name is required!" |
| age | Valid number > 0 | "Age must be a valid number greater than 0!" |
| gender | Required | "Gender is required!" |
| phoneNumber | Required, non-empty | "Phone number is required!" |
| consentGiven | Must be true | "Consent for examination/treatment is required!" |

## Data Conversion During Submission

```javascript
// 1. Type Conversions
```

## Complete User Flow

```
1. User clicks "Add Participants" tile
   ↓
2. Frontend calls getCampsByClinicId(clinicId)
   ↓
3. Add Participants form opens
   - Camp dropdown populated with camps from database
   ↓
4. User selects camp from dropdown
   - campId is set automatically
   ↓
5. User fills form fields:
   - Participant name *
   - Age *
   - Gender *
   - Phone number *
   - Date of birth
   - Email
   - Parent/Guardian name
   - Student/Staff type
   - Class/Standard
   - Roll number
   - Department
   - Dental issues (checkboxes)
   - Medical history
   - Medications
   - Allergies
   - Consent checkbox *
   - Photo consent checkbox
   ↓
6. User clicks "Add Participant" button
   ↓
7. Frontend validates all required fields
   ✗ If validation fails → Error toast shown, form stays open
   ✓ If validation passes → Continue to step 8
   ↓
8. Frontend converts data:
   - age: String → Integer
   - existingDentalIssues: Array → CSV String
   - Trims whitespace from text fields
   - Provides empty string defaults for optional fields
   ↓
9. Frontend sends POST request to:
   POST /Camp/AddCampParticipant
   {
     campId,
     enterpriseId,
     clinicId,
     participantName,
     age,
     gender,
     phoneNumber,
     dateOfBirth,
     email,
     ... (other fields)
   }
   ↓
10. Backend receives request in AddCampParticipant method
    - Deserializes JSON to CampParticipantRegistrationModel
    - Validates model
    - Saves to database
    - Generates participantId
    ↓
11. Backend returns:
    { "participantId": 42 }
    ↓
12. Frontend receives response
    - Shows success message: "✅ Participant added successfully! ID: 42"
    - Closes modal
    - Resets form
    - Clears campId and camps array
    ↓
13. Toast notification disappears after 4 seconds
    ↓
14. Ready for next participant registration
```

## Common Issues & Solutions

### Issue: "Camp ID is missing"
**Cause**: campId not set when form submitted
**Solution**: Make sure to select a camp from dropdown first

### Issue: "Participant name is required"
**Cause**: Participant name field is empty or only whitespace
**Solution**: Enter participant's full name

### Issue: "POST /Camp/AddCampParticipant 400 Bad Request"
**Cause**: Invalid data format or missing required field
**Check**:
1. Age is valid number
2. Gender is selected
3. Phone number is provided
4. Consent checkbox is checked
5. Check error message in response

### Issue: "Network error - Failed to fetch"
**Cause**: Backend not running or wrong URL
**Solution**:
1. Start backend: `dotnet run`
2. Verify it runs on port 7104
3. Check CORS configuration

### Issue: Participant ID not displayed
**Cause**: Response not properly parsed
**Check**: Network tab shows successful response with participantId
